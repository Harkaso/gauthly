# Security Policy

Thank you for helping to keep **Gauthly** and its users secure. This document explains how to report a security vulnerability and what to expect after you do.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, pull requests, or discussions.** Public disclosure of an unpatched vulnerability puts users at risk.

Instead, please report it privately through GitHub's [private vulnerability reporting](https://github.com/Harkaso/gauthly/security/advisories/new) feature (the **"Report a vulnerability"** button in the repository's *Security* tab).

## What to Include

To help assess and reproduce the issue quickly, please include as much of the following as you can:

- The affected version, tag, or commit SHA.
- A clear description of the vulnerability and why you believe it is security-sensitive.
- Steps to reproduce, or a proof of concept.
- Any relevant logs, requests, or payloads.
- The potential impact.
- Any suggested mitigation or fix, if you have one.

## Response Process

This is an open-source project maintained on a best-effort basis. You can reasonably expect:

- **Acknowledgment** of your report within a few days.
- An **assessment** of the issue and follow-up on next steps once it has been reviewed.
- If the issue is confirmed, a **fix** will be prepared and released as soon as is practical.

I aim to keep you informed of progress and will coordinate the timing of any public disclosure with you when appropriate.

## Coordinated Disclosure

To protect users, please:

- Give a reasonable amount of time for the issue to be investigated and patched before any public disclosure.
- Avoid accessing, modifying, or deleting data that does not belong to you while investigating.
- Act in good faith and avoid privacy violations, service disruption, or data destruction.

Once a fix is ready, the vulnerability may be disclosed publicly through a [GitHub Security Advisory](https://github.com/Harkaso/gauthly/security/advisories), and your contribution will be credited if you wish.

## Supported Versions

As an actively developed project, security fixes are applied to the latest version on the `dev` branch.

## Scope

This policy applies to the source code of this repository. Vulnerabilities in third-party dependencies should be reported to their respective maintainers, though you are welcome to let me know so the dependency can be updated.
